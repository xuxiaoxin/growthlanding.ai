## 需求描述

**背景**: 独立开发者、小型工具站站长、AI 产品创业者有产品但没有流量，不懂 SEO 或不想花时间做 SEO，希望快速获取自然搜索流量。

**目标**: 帮用户在 10 分钟内，输入产品描述后自动生成 10 个可以直接上线的 SEO 页面（含标题、Meta Description、URL slug、正文、FAQ、CTA）。

**价值**: 把热点趋势变成 SEO 流量页面，像 Midjourney 生成图片一样生成 SEO 页面。验证用户是否愿意使用「输入产品 → 自动生成 SEO 页面 → 获取自然流量」的工具。

## 用户故事

**角色**: 独立开发者 / 小型工具站站长 / AI 产品创业者

- **故事 1**: 作为独立开发者，我希望输入一句产品描述就能自动生成 SEO 页面，以便快速获取搜索流量
- **故事 2**: 作为工具站站长，我希望看到生成过程的实时反馈，以便确信 AI 正在工作
- **故事 3**: 作为 AI 产品创业者，我希望一键导出所有页面的 Markdown / HTML，以便快速发布到我的站点

## 功能需求

### 1. 核心功能

- [ ] F1: 首页 - 产品信息输入

  - 提供核心输入框：产品描述（必填）
  - 辅助输入：产品 URL（可选）
  - 折叠高级选项：目标用户（可选）
  - 提供「示例填充」按钮，降低使用门槛
  - 验收标准：用户能在 30 秒内完成输入并点击生成

- [ ] F2: 生成过程页 - 实时进度展示

  - 展示步骤状态：理解产品 → 查找热点 → 生成关键词 → 创建 SEO 页面
  - 实时进度条
  - 动态日志流（如 "🔥 Found trend: DeepSeek"、"📝 Creating page #3..."）
  - 预估时间提示：20-40 秒
  - 验收标准：整个过程有持续动态变化，无静态 loading 或"假死"状态

- [ ] F3: 产品理解模块（Product Parser）

  - 输入产品描述，输出：产品类别、核心关键词、用户意图
  - 支持 URL 抓取增强理解（可选）
  - 验收标准：准确提取产品类别和至少 3 个核心关键词

- [ ] F4: 热点筛选模块（Trend Selector）

  - 从人工维护的热点池中，根据产品相关性筛选 Top 10 热点
  - 每个热点标注搜索意图
  - 验收标准：返回与产品相关的 10 个热点，相关性合理

- [ ] F5: 关键词生成模块（Keyword Engine）

  - 每个热点生成 3-5 个长尾关键词
  - 关键词需具备搜索需求且可做 SEO
  - 验收标准：每个热点至少 3 个关键词，覆盖不同搜索意图

- [ ] F6: 页面生成模块（Landing Page Generator）

  - 固定模板结构：引入热点 → 用户问题 → 解决方案 → 产品推荐 → FAQ → CTA
  - 每个页面包含：SEO Title、Meta Description、URL slug、H1/H2/H3、正文（1000-1500 字）、FAQ（3-5 个）、CTA（导向用户产品）
  - 支持不同产品类型的模板适配
  - 验收标准：生成 10 个结构完整的页面，内容可读、CTA 正确指向用户产品

- [ ] F7: 结果页 - 展示与操作

  - 顶部统计摘要（生成页面数、关键词数、基于趋势数）
  - 左侧页面卡片列表：每张卡片显示 Trend 标签、关键词、标题、操作按钮（预览/复制/下载）
  - 右侧页面预览区：模拟真实网页样式，可滚动
  - 验收标准：用户能快速浏览所有卡片，点击预览查看完整内容

- [ ] F8: 导出模块

  - 支持复制单个页面的 Markdown
  - 支持复制单个页面的 HTML
  - 支持一键下载全部页面
  - 验收标准：导出内容格式正确，可直接用于发布

### 2. 边界情况

| 场景               | 预期行为               | 处理方式                      |
| ------------------ | ---------------------- | ----------------------------- |
| 产品描述过短（<5字）| 提示用户补充描述       | 输入框下方提示最小字数        |
| 产品描述无关内容   | 正常生成，结果可能不佳 | 不做拦截，信任用户输入        |
| LLM API 超时       | 显示超时提示           | 提供重试按钮                  |
| LLM 返回格式异常   | 静默处理异常部分       | 展示已成功生成的部分          |
| 部分热点无匹配     | 返回有效热点           | 少于 10 个时提示实际生成数量  |
| 网络中断           | 显示网络错误           | 提供重试按钮                  |

### 3. 性能要求

| 指标             | 要求          | 验证方法        |
| ---------------- | ------------- | --------------- |
| 首页加载时间     | < 2s          | Lighthouse 测试 |
| 全流程生成时间   | 20-40s        | 计时测试        |
| 单页面生成时间   | < 5s          | 接口耗时监控    |
| 结果页渲染       | < 1s          | 10 个卡片渲染   |

## 技术实现

### 前端实现

**技术栈**: Next.js + Tailwind CSS

**页面路由**:

- `/` — 首页（输入页）
- `/loading` — 生成过程页
- `/result` — 结果页

**关键点**:

1. 生成过程使用 SSE（Server-Sent Events）实现实时进度推送
2. 暗色主题设计系统：背景 `#0B0F14`、主色 `#4F46E5`
3. 字体 Inter / System UI，圆角 12px/16px
4. 动效：Loading 页打字效果 + 进度条，卡片 hover scale + 阴影

### 后端接口

| 接口                     | 方法 | 说明                         |
| ------------------------ | ---- | ---------------------------- |
| `/api/generate`          | POST | 提交产品描述，启动生成流程   |
| `/api/generate/:id/stream` | GET  | SSE 流式获取生成进度和结果   |
| `/api/generate/:id`      | GET  | 获取完整生成结果             |
| `/api/export/markdown`   | POST | 导出指定页面的 Markdown      |
| `/api/export/html`       | POST | 导出指定页面的 HTML          |

**LLM 调用链路**:

1. Product Parser → LLM 提取产品信息
2. Trend Selector → 从热点池匹配 + LLM 筛选
3. Keyword Engine → LLM 生成长尾关键词
4. Landing Page Generator → LLM 逐个生成页面内容

### 交互流程

1. 用户在首页输入产品描述（或点击示例填充）
2. 点击「Generate SEO Pages」
3. 跳转生成过程页，实时显示进度和动态日志
4. 生成完成后自动跳转结果页
5. 用户浏览卡片列表，点击查看预览
6. 用户复制/下载所需页面

### 状态设计

- **Loading**: 生成过程页持续动态更新
- **Empty**: 首页初始状态，引导用户输入
- **Error**: API 错误/超时，显示错误信息 + 重试按钮
- **Success**: 结果页展示完整生成内容

## 风险评估

| 风险                | 影响 | 应对措施                          |
| ------------------- | ---- | --------------------------------- |
| LLM 生成内容质量不稳定 | 高 | 设计固定模板结构，减少自由发挥空间    |
| LLM API 响应慢/超时  | 高 | 流式返回，超时重试，展示部分结果     |
| 热点池内容不足       | 中   | MVP 人工维护，持续补充              |
| 生成时间过长用户流失 | 中   | 实时进度反馈 + 动态日志增强感知      |
| SEO 页面被搜索引擎判定低质 | 中 | 模板结构优化，确保内容可读性         |
