## 需求描述

**背景**: 当前用户必须配置 DeepSeek API Key 才能体验产品，增加了理解成本的摩擦。首次访问的用户无法快速感知产品价值，容易流失。

**目标**: 在首页增加「体验 Demo」入口，用户点击后用预置的 Dummy 数据模拟完整生成流程（首页 → 加载页 → 结果页），让用户在 30 秒内理解产品能做什么。

**价值**: 降低用户理解门槛，提高首次访问转化率。Demo 体验让用户在无需任何配置的情况下"感受到"产品的核心价值主张。

## 用户故事

**角色**: 首次访问的潜在用户（独立开发者 / 工具站站长 / AI 产品创业者）

- **故事 1**: 作为首次访问用户，我希望一键体验 Demo 就能看到完整的生成效果，以便快速判断这个工具是否适合我
- **故事 2**: 作为首次访问用户，我希望 Demo 的生成过程和真实生成一样有进度反馈，以便我相信真实场景下也是这样运作的
- **故事 3**: 作为首次访问用户，我希望体验完 Demo 后能方便地开始真实生成，以便我快速上手

## 功能需求

### 1. 核心功能

- [ ] F1: 首页 Demo 入口

  - 在首页生成按钮旁增加「体验 Demo」按钮，视觉上与主按钮区分
  - 点击后跳转 `/loading?demo=true`
  - 按钮文案明确标识为 Demo 体验（如 "🎬 体验 Demo"）
  - 验收标准：按钮位置显眼，用户能在一眼内看到并理解用途

- [ ] F2: Dummy 数据模块

  - 创建 `src/lib/data/demo-data.ts`，预置完整的生成结果
  - Dummy 产品描述：一个帮助老师用 AI 批改学生作文的工具
  - 包含完整的 10 个 LandingPage 数据（标题、正文、FAQ、CTA 等）
  - 包含 ParsedProduct、Trend、KeywordGroup 等中间数据
  - 模拟 SSE 事件序列（parsing → parsed → selecting_trends → ... → complete）
  - 验收标准：Dummy 数据结构完整、内容合理、与真实生成结果格式一致

- [ ] F3: 模拟生成流程

  - Loading 页检测 `demo=true` 参数时，使用 Dummy 数据模拟 SSE 流
  - 通过 `setTimeout` 按时间间隔逐步推送 SSE 事件，模拟真实生成节奏
  - 总时长控制在 15-20 秒（略快于真实生成的 30-40 秒，Demo 不宜让用户等太久）
  - 每个阶段的间隔时间：理解产品 2s → 查找热点 3s → 生成关键词 3s → 创建页面 1s/页
  - 验收标准：进度步骤和日志与真实流程完全一致，用户感知不到是模拟

- [ ] F4: Demo 结果页标记

  - 结果页顶部 header 增加「Demo」标签，提示用户这是示例数据
  - 在 Demo 标签旁提供「开始真实生成」按钮，链接回首页
  - 验收标准：用户能清楚区分 Demo 数据和真实生成结果

### 2. 边界情况

| 场景                     | 预期行为                     | 处理方式                        |
| ------------------------ | ---------------------------- | ------------------------------- |
| 直接访问 `/loading?demo=true` | 正常展示 Demo 流程       | 不依赖 sessionStorage 中的输入  |
| Demo 流程中用户刷新页面   | 重新开始 Demo 流程          | Demo 流程无状态，可重复体验     |
| Demo 期间切换到其他页面   | 正常跳转                    | 不清理状态                      |
| 浏览器不支持 sessionStorage | Demo 仍可正常工作         | Demo 数据直接在页面内生成       |

### 3. 性能要求

| 指标               | 要求      | 验证方法     |
| ------------------ | --------- | ------------ |
| Demo 总时长        | 15-20s    | 计时测试     |
| Dummy 数据加载     | < 100ms   | 即时加载     |
| 页面切换           | < 500ms   | 无感知延迟   |

## 技术实现

### 前端实现

**新增文件**:

- `src/lib/data/demo-data.ts` — Dummy 数据（SSE 事件序列 + 10 个 LandingPage + 产品信息）

**修改文件**:

- `src/app/page.tsx` — 增加「体验 Demo」按钮，点击跳转 `/loading?demo=true`
- `src/app/loading/page.tsx` — 检测 `demo=true` 参数，使用 `simulateDemo()` 替代真实 API 调用
- `src/app/result/page.tsx` — 读取 sessionStorage 中的 `is_demo` 标记，显示 Demo 提示

**关键点**:

1. Demo 流程与真实流程共享 `GenerateProgress` 和结果页组件，不重复开发
2. `simulateDemo()` 函数在 `demo-data.ts` 中实现，返回与真实 SSE 相同格式的事件序列
3. 通过 `setTimeout` 链式调用模拟时间间隔，组件逻辑无需修改

### 交互流程

1. 用户点击「体验 Demo」
2. 跳转 `/loading?demo=true`
3. Loading 页检测 demo 参数，启动模拟 SSE 流
4. 15-20 秒内逐步展示进度（与真实流程一致）
5. 完成后跳转结果页，sessionStorage 写入 `is_demo: true`
6. 结果页展示 Demo 标记 + 「开始真实生成」按钮
7. 用户可正常使用导出功能
