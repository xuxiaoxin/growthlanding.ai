# GrowthRadar — agent orientation

## What this project is

A public **ProductHunt-style leaderboard** (`GrowthRadar`) of newly launched,
worth-studying SaaS/AI products. A **curated, featured-only** static site
rendering data produced by the sibling `monitors/` + `analyzers/` pipeline.

This directory was previously a different product (a C-side SEO landing-page
generator) — that product was **fully removed**; only the build config, design
tokens, and root layout were kept.

## Architecture (static-only SSG — no client data fetch)

The site is **100% statically generated** at build time:
- `src/lib/data-server.ts` reads `public/data/*.json` via Node `fs` during
  `next build`. This module uses `fs` and MUST stay server-only (never imported
  into client components, or it leaks into the client bundle).
- `/` (home) — Server Component, prerendered with all featured cards.
- `/category` — category index page (gateway to the 13 categories).
- `/category/[cat]` — Server Component, `generateStaticParams` returns the 13
  category slugs, `dynamicParams = false` (unknown slug → 404). These are core
  SEO pages (blue-ocean "new/latest {category}" queries).
- `/domain/[domain]` — Server Component, `generateStaticParams` returns the ~775
  featured domains, `dynamicParams = false` (non-featured → 404). One static
  HTML per domain.
- `/about`, `/privacy`, `/terms` — 3 static trust/legal pages.

Total: ~799 static pages (1 home + 1 category index + 13 category + ~775
domain + 3 trust + sitemap.xml + robots.txt + not-found).

No `use client` data fetching remains. Pages are instant (CDN) and SEO-friendly
(full content in initial HTML).

## SEO 体系

- **4-layer internal-link graph:** Home → `/category` → `/category/[cat]` →
  `/domain/[domain]`. The category index and footer expose category gateways;
  category pages link out to every domain in the category; domain pages link
  back to their category. No page is an orphan.
- **JSON-LD:** home = `ItemList`; category pages = `BreadcrumbList` +
  `ItemList`; domain pages = `SoftwareApplication` + `BreadcrumbList`.
- **Thin-content handling:** detail pages with no description AND not alive
  are auto-marked `noindex,follow` (keep link equity flowing without indexing
  empty pages). Normal pages are `index,follow`.
- **Crawl infra:** `src/app/sitemap.ts` (emits category + domain URLs),
  `src/app/robots.ts`, per-page `canonical`, and `metadataBase` in
  `layout.tsx`.
- **Category blue-ocean strategy:** category H1/intro target "new/latest
  {category}" (low-competition) rather than the crowded "best {category}"
  SERP. Wording is generated by `src/lib/categories.ts`.

## Categories (13)

The canonical category slugs (keys of `CATEGORY_META` in
`src/lib/categories.ts`; must match `category` values in `featured.json`):

`ai_tool`, `saas`, `marketing`, `developer_tool`, `finance`, `other`,
`ecommerce`, `healthcare`, `productivity`, `education`, `content`, `design`,
`communication`.

`other` is a catch-all and is sorted last in the UI.

## CRITICAL: desensitization

This site is **public**. The export pipeline (`analyzers/scripts/export-webui.py`)
strips all internal detection signals so the ranking methodology can't be
reverse-engineered. **Do not add back** to the public output: `score_breakdown`,
`dns_richness`, `page_count`, `has_pricing_page`, `has_payment_sdk`,
`payment_provider`, `internal_links`, `sitemap_url`, `alive_30d`, `monetized_at`,
tranco, crux, survival-window booleans, etc.

What IS public: the score (bare number), LLM analysis (category/summary/
description/key_features/target_users/why_interesting/replication_difficulty/
competition_level), and survival_status (alive/dead — publicly observable).

## Data contracts

`src/types/index.ts` mirrors `export-webui.py` output. Three-state semantics
apply to the few booleans that remain (**null = "not measured" ≠ false** —
never coerce to a boolean).

`stats.json` is **out of sync** — do not read category counts from it. All
category-level data (counts, lists) must be **derived from `featured.json`**
at build time.

## Data refresh flow

1. Run `analyzers/scripts/export-webui.py` on bishenai2 (reads internal MySQL,
   emits desensitized JSON).
2. rsync output into `public/data/`.
3. `npm run build` to verify, then commit + push (dual-push to private + public
   repo). The push triggers a Vercel rebuild.

## Design tokens (globals.css `@theme inline`)

Light "editorial" theme (warm off-white, single brand accent):
background `#fafaf9` (stone-50), foreground `#18181b` (zinc-900), card
`#ffffff`, primary ink `#18181b`. Single accent is **teal `#0d9488`** (with
`-soft`/`-ink` variants), used sparingly (logo, Top3, score ring, focus).
`--color-fresh` amber `#d97706` for the NEW pill. Difficulty levels use a
same-hue teal gradient (low=zinc / medium=teal-600 / high=teal-700) — no
red/yellow/green traffic-light, by design.

## Git remotes

`origin` dual-pushes to `growthlanding-ai/webui` (private) and
`xuxiaoxin/growthlanding.ai` (public, Vercel deploys from this). One `push`
hits both; the public push triggers a Vercel rebuild.

## 产品决策 (product constraints)

- **No AI/LLM mention in user-visible copy.** Describe the analysis with
  vague wording (e.g. "analysis", "identified"); never call out AI/LLM.
- **No contact info anywhere** — no email, no contact form, nothing.
- **zsh globbing gotcha:** `[domain]` and `[cat]` are glob patterns in zsh.
  Always quote these paths in shell/git commands (e.g.
  `git add 'src/app/domain/[domain]/page.tsx'`), or tab-completion/git will
  misbehave.
